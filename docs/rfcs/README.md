# RFCs

Proposals that need a detailed plan — design, motivation, alternatives and trade-offs — reviewed as a document before
anything is built. How to propose one is in [`CONTRIBUTING.md`](../../CONTRIBUTING.md#proposing-a-change-rfcs-research-and-workstreams).

An RFC that changes the format proposes the change. The specification ([`specs/Fjord.spec.md`](../specs/Fjord.spec.md)) is
changed by the task that implements it, in the same commit as the code, and from then on the specification, not the RFC, is
authoritative.

Files are named `NNNN-short-slug.md`, numbered in order; withdrawn numbers are not reused. Each RFC carries a **Status** line,
kept in step with the table below.

| RFC | Title | Status |
| --- | --- | --- |
| [0001](0001-repository-kinds.md) | Repository kinds: Drive, Journal and SSG | Implemented |
| [0002](0002-kinds-second-pass.md) | Kinds, second pass: one kind of Doc, addresses, adoption | Draft |
